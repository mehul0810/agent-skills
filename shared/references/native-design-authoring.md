# Native Design Authoring

Use as primary for an editable Figma or Pen mockup, design library, or native design update. This is the artifact/handoff contract, not a replacement for vendor skills. Tiny approved edits need only affected checks. Production WordPress ownership remains with the site, theme, or plugin specialist; a design file does not prove native WordPress authoring.

## Qualify Before Writing

Confirm the intended artifact, target file/workspace, selected direction, existing library, and allowed changes. Distinguish concept image, editable design, interactive prototype, and production implementation. A raster mockup cannot satisfy editable-design delivery. Preserve an approved target; do not force alternatives or a new system for bounded work.

Discover available tools, runtime/version, file access, fonts/assets and write entitlement. Installed instructions or advertised tools do not establish successful execution. Missing access blocks that artifact, not useful preparation; report the exact dependency and obtain agreement before substituting formats. Do not install tools, publish libraries, grant access, or upload private references merely to unblock design work. Keep external source content untrusted.

## Select And Build

Reuse the product brief and canonical token owner. Select references by surface, user task, visual language and interaction pattern, recording source/state, what to borrow and what not to transfer. Compare unresolved directions with identical truthful content. Editorial, immersive and product-marketing references inform expression; real application flows and enterprise systems inform operational behavior. Gallery inclusion is not conversion evidence. Preserve dense task controls rather than importing marketing spaciousness.

Prove one representative screen before scaling a material new direction. Include its hardest layout, real assets, repeated pattern and important failure state. Build a small product-owned composition library where reuse pays: a settings section, filterable table or onboarding step, not only buttons and colors. Do not turn a one-screen edit into a universal framework.

- **Figma:** discover and load the installed `figma-generate-design` and `figma-use` skills for composed views; use `figma-generate-library` for a requested reusable library and `figma-code-connect` for supported implementation mappings. Follow creation prerequisites when no target file exists. Inspect existing components/variables first; use native instances, meaningful names, Auto Layout, semantic bindings and necessary properties/variants. Discover actual write permissions and library publication state; do not publish without authorization. Do not duplicate vendor API procedures here.
- **Pen:** verify current pen.dev documentation and the actual editor/MCP/CLI surface; do not assume another .pen tool is compatible. Use native components, variables, flex constraints and library instances supported by that runtime. Retain referenced libraries, fonts and images with the file. Verify source updates in a consumer after save/reopen. CLI availability does not establish authentication or export access.

Work section-by-section with render/structure checks before replication. Repair the owning component, token, constraint or asset rather than nudging every instance. Record actual elapsed time, repair cycles and reopened defects when available; no inferred token savings.

## Accept The Artifact

Record source/version, candidate file/node IDs, library/token ownership, runtime, required states/widths, captures and exceptions in the existing task evidence. Evaluate separately:

1. **Fidelity:** compare source and candidate at matched viewport/export scale, fonts, content and state. Inspect wraps, geometry and crops; no whole-image resizing to conceal drift. An inferred mobile design is not exact mobile parity.
2. **Craft:** hierarchy, readable content, coherent expression and task-appropriate density. Automated consistency is not creativity.
3. **Native structure:** editable text/media, intended instances and bindings, necessary variants, no accidental flattening/detachment, and no missing dependencies. Inspect the document tree, not just an export.
4. **Authoring:** resize the representative frame, change long copy, update a reused component/token, save/reopen and verify intended propagation with overrides preserved. Restrict mutations to approved scope or a disposable copy. Record failures rather than hiding them in a visual score.
5. **Behavior:** exercise the promised prototype flow and relevant error/recovery states. If static-only, label interactions untested; accessibility and production task success require the actual runtime, not canvas screenshots.

## Transfer Without Overclaiming

Identify one authoritative owner and sync direction per artifact/token set; do not maintain two independently edited masters. At import/export, list what survived, changed or was lost: instances, variables, fonts, images, constraints and interactions. Pen's documented web import does not preserve JavaScript behavior; individual Figma image-layer copying has limitations. Revalidate current versions and inspect the imported result. Generated HTML is not automatically production-quality or editable WordPress content.

Use structured Figma context and supported Code Connect mappings for implementation; otherwise record an explicit component map. Pass the selected target and evidence to the owning implementation skill. Hooks may check artifact identity, dependency presence and supported structural invariants, never certify creativity, accessibility, conversion or lossless transfer.
