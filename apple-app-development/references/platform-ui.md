# Platform and UI

Use the [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) for the target you are changing. Share domain and persistence code where it fits; share a screen only if people can actually complete the task with each platform's layout and input. Apple's [Food Truck sample](https://github.com/apple/sample-food-truck) illustrates shared code and platform-specific presentation, not a deployment target or required architecture.

| Target | What to implement and try |
|---|---|
| [iPhone](https://developer.apple.com/design/human-interface-guidelines/designing-for-ios) | A reachable primary action, safe areas and familiar Back behavior. Try the task with large text and the software keyboard visible; don't leave the only action under it. |
| [iPad](https://developer.apple.com/design/human-interface-guidelines/designing-for-ipados) | Adapt navigation to the *window*, not the device name. Preserve selection as columns collapse; try a narrow window, then a wide one, including touch and keyboard/pointer input. |
| [Mac](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos) | Place commands in the expected menu, preserve keyboard equivalents, window resizing, focus and selection. Choose native AppKit for an existing desktop contract rather than stretching a phone layout. |
| [Apple Watch](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos) | Put the useful result or quick action first. Try a small display, Digital Crown scrolling where appropriate, interruption and return. Don't silently require a live paired phone for a promised independent action. |
| [Apple TV](https://developer.apple.com/design/human-interface-guidelines/designing-for-tvos) | Design for viewing distance and directional focus. Use a remote to reach every action, select, go back, and recover focus after a modal or list update. A grid that works with a pointer isn't proof. |
| [Vision Pro](https://developer.apple.com/design/human-interface-guidelines/designing-for-visionos) | Start a conventional task in a window; choose volume or immersion only for a spatial need. Support comfortable indirect selection, adequate target spacing and an exit. A simulator cannot establish headset comfort. |

**Implementation choices.** Preserve navigation, state and storage ownership across a change. Use stable model identity, a single owner for mutable state, and bindings for edits; a view redraw must not trigger duplicate fetches or lose drafts. Match observation APIs to the deployment floor ([model data](https://developer.apple.com/documentation/swiftui/managing-model-data-in-your-app)). Bridge a single missing control with [UIKit integration](https://developer.apple.com/documentation/swiftui/uikit-integration) or the AppKit equivalent before proposing a rewrite. For a new API, check *OS availability*, guard it and test the fallback, or stay with the older supported equivalent.

**Responsiveness and access.** Scope asynchronous work to the feature lifetime, cancel superseded requests and don't let stale results replace newer ones. Keep blocking I/O and expensive decoding off the main actor; `async` alone doesn't move work off it. For a hitch, replay the same interaction and dataset with [Instruments](https://developer.apple.com/documentation/Xcode/understanding-and-improving-swiftui-performance); distinguish expensive individual updates from many unnecessary ones before changing state ownership or caching.

Use system controls, semantic labels and values, scalable typography where supported, and localized strings/plurals. Exercise long translations, contrast, reduced motion and relevant keyboard/focus paths. Don't make color, sound or a gesture the only cue. An [accessibility audit](https://developer.apple.com/documentation/accessibility/performing-accessibility-audits-for-your-app) covers the screen and checks actually run, not full accessibility conformance. Honor the owner's exclusions for macOS VoiceOver and narration; don't run, request or substitute those checks or mark them passed.
