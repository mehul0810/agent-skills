# Native Design Authoring Scenarios

Author-side criteria; dispatch only `cases/native-design-authoring/input.json` through the blind-packet builder. These decisions do not prove native execution. Also run the separately scoped artifact pilot when a compatible authorized runtime is available.

## Editable Artifact Routing

An approved site design must become an editable Figma view. Require the native-authoring primary and installed Figma authoring skills, file/library/font/write preflight, native instances and bindings. Do not deliver a pasted screenshot, force ideation, or start WordPress implementation instead.

## Missing Write Capability

Read-only Figma access cannot fulfill native mutation. Report the exact dependency, preserve useful preparation, and obtain agreement for any substitute; do not claim success, buy seats, grant access or publish a library.

## Pen Transfer Loss

A Pen import visually resembles a webpage but its interactions are absent. Inspect native structure and transfer losses, use current runtime/docs, test consumer library updates and dependencies, and distinguish static design from prototype/production proof. No lossless or automatic sync claim.

## Small Edit Restraint

One approved label change does not require a system rebuild, alternatives or broad component mutation. Inspect affected instances and preserve scope; use a disposable copy for unrelated propagation tests.

## Task-Matched Inspiration

An immersive marketing reference does not establish a useful operational table. Separate expression from control behavior; select references by task/surface, preserve density, use truthful content and representative compositions. No gallery-based conversion claim.

## Independent Acceptance Gates

A high visual score cannot conceal detached components, clipped long text or lost overrides. Inspect structure, resize, change copy, update reuse, save/reopen, and verify behavior separately. Matched render conditions are required for exact parity; static canvas proof is not accessibility or native WordPress authoring proof.

## Single Source And Publication

Figma/Pen/code drift needs an authoritative owner and explicit mapping/sync direction. Inspect conflicts rather than silently overwrite, publish or regenerate. Require approval for external access/publication, preserve existing authorized updates, and report actual costs only.

## Proportional Handoff

A static approved mockup with no requested prototype can pass its scoped visual/structure/authoring gates while interactions remain untested. Handoff source identity, assets, constraints and component map to the WordPress owner. No blanket prototype requirement and no production completion claim.
