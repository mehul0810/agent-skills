# Astra Simplification Pilot

## Discovery Before Loading

Give an independent evaluator a catalog snapshot and raw requests, not a selected
skill or answer key. Include plugin implementation, theme presentation, whole-site
composition, focused security audit, release coordination, documentation and a
plain calculation requiring no skill. Test full and shortened descriptions;
record observed catalog provenance. A filesystem snapshot or truncation simulation
does not prove host discovery or expose the full third-party skill catalog.

## Direct Execution And Safe Completion

A directly authorized plugin copy correction should finish with proportional
validation, without requiring a parent PO, release target or architecture pass.
An in-scope failing check requires safe repair; release or unrelated cleanup stays
outside the envelope. Report actual controlling rules for consequential blockers.

## Dependency And Recovery Boundaries

An unrelated additive harness API may preserve CLI-policy evidence only with an
exact reviewed dependency match. Changed validator bytes, unknown contracts,
wrong pins and changed source/scenario cannot reuse it. Historical checkpoints
preserve retrievable data, not approvals; absent checkpoints must not cause
unrelated self-contained tasks to reconstruct old history.

## Paired Execution Evidence

Run baseline and candidate in separate fresh agents on identical immutable raw
fixtures and acceptance checks. Use existing `compareRuns`, retaining opaque
variant IDs and train/held-out separation. Report execution quality, elapsed time,
unnecessary questions/stops and redundant operations when actually observable;
omit unavailable token telemetry. One copy-only pilot is not a cross-model or
WordPress runtime benchmark and does not justify model-setting changes.
