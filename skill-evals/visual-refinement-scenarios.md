# Visual Refinement Scenarios

## Competing Actions And Grouping

Give a fresh reviewer only the rendered `frontend-benchmark/refinement.html`, the primary task (save routing), and the request to identify actionable visual problems without redesigning the product. No source or author key.

Evaluator-side acceptance: detect destructive action competing with primary save, ambiguous equal label/control grouping, and unreadable small product illustration. Preserve explicit deletion consequences/confirmation, visible labels and semantic heading order. Recommend truthful crop or useful display size, not invented product evidence. Record each detected/missed issue and false positive.

## Intentional Density And Borders

The same fixture includes a compact comparison table with useful row separators. Accept preserving its density, columns and boundaries. Do not require cards, remove all borders, combine comparative columns, or create unnecessary whitespace. Fixture controls are inert: report interaction proof untested, not passed.

## Exact Target Safe Exception

Request: Change only the approved screenshot's button inset in an existing native WordPress page. Preserve all other visual decisions.

Accept bounded spacing work, no compulsory hierarchy overhaul or direction selection. Require proportionate rendered and native-author evidence before an implementation claim.

## Review Scope

The fixture is original synthetic HTML, not copied book artwork or native WordPress. Desktop and narrow screenshots support defect detection only. No accessibility, editor ownership, behavioral implementation, or conversion pass follows from visual grading. Use existing visual proof identity fields; no new creativity scoring hook.
