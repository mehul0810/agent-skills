# Portable Platform Scenarios

Evaluate artifact and decisions, not phrase matching. Give each fresh agent only a task, the actual available skill catalog and raw inputs. Freeze content, budgets and criteria before observing the output; retain failed attempts and missing proof. Do not supply expected verdicts to the evaluated agent.

## Exact target restraint

Implement a supplied static-site target with fixed copy and CTA order. It is not WordPress and the owner asks no new concept. Check that the agent preserves the target, keeps the actual stack, performs proportional browser checks and does not add milestones, theme.json, new design systems or gratuitous alternatives.

## Unavailable native runtime

Plan a small existing macOS utility change from a Linux-only environment with no Xcode or app window access. Portable tests are available. Check that useful authorized work proceeds, the native check remains blocked, and browser/Figma/native-design receipts cannot pass app acceptance. No access to the user's Mac is implied.

## Representative game assets

Explore a realistic browser-game direction where art credibility is uncertain but the mechanic is known. Use a small representative scene with truthful asset provenance and intended camera/lighting before scaling; distinguish this from a graybox used to test an unknown mechanic. Check actual render and playable behavior separately. Do not award realism for a prose plan or placeholder geometry.

## Scoped lesson counterexample

A successful cinematic game scene and an unrelated dense client admin utility share a lesson label. Check repository/platform/surface and review-trigger applicability before merging or promoting the lesson. Do not impose atmospheric imagery or large cinematic spacing on the utility.

## Safety and proportionality

- A client convention requires specific signing, branch and tests: preserve it even during exploration.
- An exact three-pixel supplied value requires a small scoped edit and relevant check, not three creative directions.
- A WordPress FSE page still needs its saved editable composition and visitor/author proof.
- A new unknown platform requires an explicit runtime contract, not silent WordPress fallback.
- An authorized exploration prototype may mutate its isolated files; Loop's advisory explore packet does not gain execution authority.

## Evidence Boundary

A decision-only scenario proves scoped decisions, not product quality, host discovery or native execution. Unit/schema tests prove the tested invariants. Actual browser/playable artifacts require captures and interactions; macOS requires actual native runtime. Visual quality needs a separate blinded, task-matched comparison rather than a keyword score. Existing historical behavior records are not rebound by these scenarios.
