# Routing Collision Scenarios

Every collision identifies one entry owner, a bounded evidence handoff, and a forbidden load or authority expansion. Do not solve ambiguity by loading both skills broadly.

| Collision | Prompt | Entry owner | Handoff | Forbidden load or authority |
|---|---|---|---|---|
| Site vs content | "Write the article copy and publish the schema-enabled WordPress page." | `wp-site-expert` for the runtime deliverable | Copy brief/result to and from `content-writer` | Content writer does not implement/runtime-prove the page; site worker does not absorb standalone writing expertise. |
| Plugin vs PO | "Implement issue #42 and prepare the release-ready brief." | `wp-product-orchestrator` | Bounded issue contract to `wp-plugin-expert`; implementation evidence returns to PO | Plugin worker does not own issue/release synthesis; PO does not implement plugin code. |
| Theme vs site | "Turn this design into an editable block theme and improve the conversion path." | `wp-site-expert` for journey/outcome | Approved outcome and visual contract to `wp-theme-expert` | Site worker does not own theme internals; theme worker does not redefine conversion strategy. |
| Plugin block vs theme | "Build a portable pricing calculator block for this plugin and style it in the active block theme." | `wp-plugin-expert` | Stable block contract to `wp-theme-expert` for presentation | Theme does not own portable functionality/data; plugin does not load broad FSE context. |
| Implementation vs independent proof | "Fix the settings bug and independently prove the packaged plugin saves it." | `wp-plugin-expert` | Observable contract and exact package/runtime to fresh `behavior-validator` | Validator receives no source, diff, tests, or implementation notes. |
| Loop Steward vs CTO | "Review and merge an agent-skills control-plane PR." | `loop-steward` | Decision outcome to CTO only when portfolio state changes | CTO does not review/merge control-plane PRs. |
| WordPress contribution vs product | "Fix Gutenberg Core behavior upstream." | `wp-contributor` | Product impact only when a downstream product needs follow-up | Product specialists do not load upstream contribution workflow. |
| Video vs product control | "Turn these brand references into a product launch video and track it for the next milestone." | `wp-product-orchestrator` for governed product state | Storyboard/render contract to `product-video-producer`; proof returns to PO | Producer does not own milestone/release approval; PO does not absorb production expertise. |
| Video vs generated visuals | "Create a product film with three generated abstract scenes." | `product-video-producer` | Governed scene brief to Creative Production or `imagegen` | Asset worker does not own storyboard, claims, timeline, or final proof. |
| Feature delivery vs focused quality review | "Build a secure plugin settings screen, then run a focused security and accessibility audit." | `wp-plugin-expert` | Exact revision and review contract to `wp-quality-reviewer`; dispositions return to artifact owner/PO | Reviewer does not absorb feature scope; plugin worker does not self-certify the focused audit. |
| Critical fix vs independent re-review | "Fix this P1 authorization bypass and prove the release candidate." | `wp-quality-reviewer` for the finding/fix contract | Non-trivial plugin implementation to `wp-plugin-expert`, then changed code/evidence to a fresh source-aware reviewer and observable contract/package to `behavior-validator` | Implementer or original reviewer does not self-certify a critical fix; validator receives no source context. |
| Quality review vs source-blind proof | "Review and fix this slow inaccessible admin flow, then independently prove the packaged behavior." | `wp-quality-reviewer` | Observable contract and package/runtime identity to fresh `behavior-validator` | Validator receives no source context; reviewer does not claim independent runtime proof. |
| Release evidence vs PO | "Is this release candidate ready for production approval?" | `wp-product-orchestrator` | Exact candidate to `wp-quality-reviewer`; technical dispositions return for PO synthesis | PO does not invent technical passes; reviewer does not own product scope or release approval. |
