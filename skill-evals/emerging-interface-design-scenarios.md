# Emerging Interface Design Forward-Test Scenarios

Use these source-blind scenarios after changing trend adoption, AI/adaptive UI, voice, typography, immersive interaction, or enterprise progressive-depth guidance. Evaluate observable routing, decisions, and proof rather than phrase matching.

For each scenario record route, references loaded, avoidable loads, classification, user/task value, fallback, required proof, forbidden behavior, and pass/fail. Pass requires one primary plus at most one justified support reference.

## Trend Pile-On Is Not A Direction

Prompt: Make this enterprise WordPress site look 2026: use maximalism, 3D, experimental navigation, kinetic type, glass effects, and gamification.

Required: inspect product, audience, brand, task, content, and runtime; classify each technique as durable, experimental, campaign-only, or decorative; choose only evidence-backed techniques; reject coercive rewards and dark patterns; define fallback, success measure, and removal path for experiments; preserve WordPress editability, navigation, accessibility, and performance.

Forbidden: treating `2026` as acceptance criteria, applying every named trend, installing an aesthetic stack by default, or calling novelty premium.

## Governed Adaptive AI Dashboard

Prompt: Personalize this plugin dashboard with AI recommendations and let the agent apply changes automatically.

Required: identify AI presence and output type; define scope/permissions, source/provenance/freshness, uncertainty, stable default, consent/data boundary, explain/reset/override, preview/approval proportional to consequence, cancel/undo/retry, audit history, and streaming/partial/failure states; require automatic actions to be allowlisted, idempotent, conflict-aware, tenant-isolated, bounded, and reversible; preserve a deterministic admin and author experience.

Forbidden: hidden personalization, decorative AI styling, unexplained ranking, fabricated citations/confidence, silent execution, generic success after partial failure, or public disclosure of sensitive internals.

## Kinetic Variable Typography

Prompt: Make every heading animate through variable-font axes so the landing page feels premium.

Required: define semantic type roles and the communication purpose of motion; reject universal animation; validate font license/source, subsets, language coverage, fallback metrics, LCP/CLS, line length, wrapping, zoom/reflow, static state, reduced motion, and intermediate widths.

Forbidden: animating because it looks expensive, unreadable/selectability-breaking text, unbounded font payload, layout shift, or no static fallback.

## Voice Workflow Requires An Equivalent Path

Prompt: Replace this settings form with a voice assistant.

Required: preserve an equivalent text/keyboard form; show permission, listening/recording, processing, transcript/confirmation, correction, cancellation, error, retention, and recovery states; minimize data and announce dynamic state accessibly.

Forbidden: voice-only completion, background capture, asking users to speak secrets, hidden retention, or executing consequential changes without confirmation.

## Immersive Product Story With Enterprise Constraints

Prompt: Turn this product page into a WebGL guided-scroll experience with nonlinear navigation.

Required: prove task or comprehension value before adoption; preserve normal scroll, deep links, history, semantic order, keyboard/touch, and content without WebGL; provide static, reduced-motion/data, unsupported-browser, and failure fallbacks; measure LCP/CLS/INP and resource cost; keep the page editable and understandable in WordPress.

Forbidden: scroll hijacking, blocked content, Chromium-desktop-only proof, frontend-only frozen markup, or accepting performance/accessibility regressions as visual tradeoffs.

## Enterprise Overview Before Selective Depth

Prompt: Put every technical detail about this complex enterprise product on one long landing page so buyers see everything.

Required: build a compact overview and role/job/risk path; use claim, proof, workflow, control, outcome, then optional deeper evidence; keep material limitations, privacy, pricing conditions, failure behavior, and support boundaries visible; prove scan and deep-dive tasks.

Forbidden: generic feature-card buckets, hiding material constraints in accordions, radical brevity that removes decision evidence, or an unstructured wall of copy.
