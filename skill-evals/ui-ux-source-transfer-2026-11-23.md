# UI and UX research: what shipped and what didn't

The [source atlas](../examples/ui-ux-source-atlas.md) records one substantive public page for each of 110 different websites. We searched for studio work, design systems, research methods and technical explanations; opened the original pages; and separated what each publisher documents from what a project might try. The sample is curated, not representative of the web. No third-party screenshots, paid libraries or example code are distributed.

## Decisions

| Finding | Existing coverage | Decision and proof |
| --- | --- | --- |
| Printed identities often provide a **relationship**, not a ready-made web layout. A rule such as a fixed catalog-number column can survive a change of title, image or slot. | The theme reference already mapped tokens and components to WordPress, but a token inventory didn't tell an editor how to make the next entry look related. | Add a repeatable rule, editable inputs, an honest missing-media treatment and a second-item check to [theme translation](../wp-expert/references/style-guide-theme-translation.md#make-a-visual-idea-repeatable). Try the *same* component in broad and narrow parents on one screen before adding a breakpoint. |
| A wrong first choice can be caused by the **wording or its presentation**. A test prompt can accidentally give away the answer. | The [UX guide](../wp-expert/references/ux-product-strategy-design-qa.md#risk-tiered-usability-evidence) already distinguishes expert walkthroughs from representative-user evidence. We tested a more specific diagnostic workflow. | Publish the [worked navigation example](../examples/navigation-study-worked-example.md) and test cases, not a default site-skill change. Use a neutral task; compare the text tree, rendered first choice and completed action. Investigate presentation, disclosure and prior exposure before attributing a difference to color or position. |
| Intrinsic layout, fluid type and container-aware components make attractive designs more tolerant of real content. | The [spatial guide](../shared/references/spatial-layout-and-alignment-system.md) and [typography guide](../shared/references/wordpress-typography-system.md) already cover their implementation and limits. | Reuse those instructions. The new same-viewport comparison tests an actual editorial constraint; it isn't another CSS tutorial or a requirement to use container queries. |
| A motion demo or gallery can inspire a treatment without proving its keyboard behavior, loading cost or effectiveness. | [Design taste](../shared/references/frontend-design-taste.md) already distinguishes inspiration, actual movement and evidence. The [product-site study](product-site-design-study-2026-11-23.md) covers still, recorded, sample and live product states. | Keep galleries as discovery aids. Do not copy identities, infer motion from a still, adopt a new library by default or claim another site's results. |
| Systems distinguish first use, failed loading, no matches and missing permissions; validation should not erase the user's work. | [Product UI](../wp-expert/references/ui-ux-pro-for-wordpress.md), [form resilience](../shared/references/interaction-and-form-resilience.md) and the existing conversion guidance already cover these decisions. | Keep the owners. Use a specific state or consequence to choose the feedback, not a universal toast, modal or blank-state illustration. |

For concrete starting points, compare [Hello Monday's interpretation of the Søstrene Grene store](https://hellomonday.com/work/soestrene-grene) with [the card in Ahmad Shadeed's container-query guide](https://ishadeed.com/article/css-container-query-guide/): the first gives an identity a rule; the second shows how to let the same component respond to its slot. For the research side, [Maze's advice on unbiased task wording](https://help.maze.co/articles/5769270783-best-practices-for-writing-tasks-and-descriptions) and [Optimal Workshop's tree-testing tasks](https://www.optimalworkshop.com/101-guides/tree-testing-101/write-your-tasks) are a better starting point than a gallery of attractive menus.

Only the verified **theme** reference changed in the installed skill set (1,421/1,500 words). The broader test for the site candidate did not clear the existing publication gate, so its runtime reference was restored byte for byte to the previously admitted version. No baseline was relaxed or replaced. The research, worked navigation example and new tests remain available for a future repair. No new top-level skill, always-loaded reference, package, worker configuration or automation was added. This is a footprint check, not a measured time saving or visitor outcome.

## What to test

The [theme cases](cases/editorial-signature/input.json) ask whether a branded relationship survives normal editorial change without per-post code and whether a caption-only edit stays bounded. The [site cases](cases/navigation-study-selection/input.json) test a neutral task, a misleading first-click claim, a repeated task with confounded results and an exact footer edit. Keep each case's scorer criteria out of performer packets.

## Design regression

The existing design suite is broader than the six new decisions. On candidate `5eb5dd1`, independent scoring found 43/56 passing check/case pairs. A focused follow-up retained those 43 and passed 8 of 13 replacements, giving 51/56. Both results were retained as failed; neither was registered as a passing baseline. Examples of omissions were the source priority for a WordPress component recommendation and the evidence needed for motion transferred between brands. These runs alone cannot establish whether the two changes caused a difference from the earlier baseline.

For the final candidate, the full development corpus was frozen again. Six independent performers made first drafts. Six other reviewers checked each complete group against its brief and frozen role guidance, without the scoring key. Both complete sets, rather than the best case from either set, were retained for separate independent scoring. This is a replay on known scenarios, not held-out evidence or a measure of success on live projects.

At `fcdfc84cb7726f95c10eada3ac540b23c6218571`, the first drafts passed 27/56 mapped pairs (6/27 whole checks); the independently reviewed drafts passed 34/56 (12/27 whole checks). The final grade SHA-256s are `fcae4071b05ca88aba5fcbe7717b297ccf0744b7c6542e3799441ff9f9c46002` and `91db0ae39375179b5921aa2555b47770deacdcd2cdfd9b2a79a3b61dd0a320e2`, respectively. The grade-bound preflights both returned valid receipts with a **failed** outcome and admission not performed. The failures included the explicit design choices required for a premium page and the source/destination observations, pause/resume and contrast-over-time proof required for reference motion. The grades measure the written answers, not implemented websites. Some agents reported truncated guidance reads or seeing neighboring raw prompts in a shared packet; no answer-key access was reported. These limits prevent interpreting the raw counts as a causal comparison.

**Release decision:** do not register either candidate run, do not weaken the rubric, and do not repeat the exercise until it passes by chance. Restore the installed site guide to the published bytes; retain the candidate commit, tests and worked example for a future repair. The theme change is independent: neither its source nor its routing changed during those site revisions. The separate theme scenarios and rendered specimen apply to the same theme guidance that ships. Private reading traces, packet freezes, grades, browser evidence and both failed preflights are retained in the dated UI/UX source survey.

## Browser specimen

A separate performer made an original, offline listening-notes archive. Its catalog-number spine remains while the record, title, source and illustration can change. The first Chromium review found real problems despite the passing theme decisions: two different records offered identically named “Read notes” links, and following an anchor scrolled without visibly focusing the destination. The first specimen and review were retained.

On the revised HTML (SHA-256 `249cf22bdf0542a8351928b21dc17538382eedad92fa35a47f8473437fd946d4`), an independent reviewer activated all 12 record links by keyboard and pointer at 320, 390 and 1440 CSS pixels. All 72 activations focused the corresponding visible note. At desktop width the alternate edition put the same long, unillustrated record in a wide and a narrow slot; neither invented art or clipped text. At both narrow widths the cards stacked without horizontal page overflow. With JavaScript disabled the edition control still worked, and 24 sampled title-link activations reached and focused their destinations.

These are synthetic decisions and observations of local Chromium, not a WordPress editor save/reopen test, physical device coverage, visitor research, a conversion result or a conformance claim. Screen-reader and narration checks were excluded by owner direction, not passed.
