# Apple app and dependency decisions

Keep this scoring sheet out of the performer packet. Read the skill through its install layout, freeze the briefs and candidate guidance, and score concrete actions rather than keyword matches.

| Case | Acceptance |
|---|---|
| 1. Native fit | Keep the iOS 14 floor and UIKit app. Provide a compatible single-item picker (for example, PHPickerViewController), cancel/failure path, local handling, and no unnecessary library-wide permission. |
| 2. Adaptive editor | Preserve draft/identity outside transient layout; prove selection, keyboard save, failure recovery and persisted success on named iPad/Mac destinations. A wide screenshot doesn't prove them. |
| 3. Other devices | Address TV focus restoration using the remote, Watch independent local completion plus deferred reconciliation, and a comfortable window/indirect selection on Vision Pro. Distinguish simulated input from hardware/comfort. |
| 4. Performance | Measure the offending interaction and distinguish expensive work from frequent invalidations before choosing a fix. Repeat with comparable data. Don't claim device performance from the simulation. |
| 5. Result identity | Honor exit 65, failed and skipped tests. Read the matching result, drill into the named failure, preserve the log if the bundle is incomplete. A parser's success or older pass cannot overrule it. |
| 6. Privacy and channels | Inventory code, actual data flows and SDK/archive declarations, required reasons/signature where applicable and store privacy details. Keep Mac Developer ID/notarization separate. Don't submit, guess declarations or change accounts. |
| 7. Minimum sufficient change | Reuse existing/native control for one date with server validation and authorization intact. Treat blackout availability as a shared server-side rule including direct API callers; add UI or a dependency only for a demonstrated remaining requirement. |
| 8. Boundaries | Route to the existing web/WordPress and editable-design workflows, respectively. No native target, Apple SDK install, or claim of running an app. |

**Native build.** Use the separate blind native-task request. Inspect the buildable project. Count a UI pass only if the visible add, termination/relaunch persistence and reset were observed on the named destination. Record build, simulator and physical-device results separately; neither a script that writes the store nor a preview satisfies the interaction requirement. Never promote this synthetic app to production, App Store, real-device or efficiency proof.
