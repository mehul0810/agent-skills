# Author-Only Criteria: Cross-Project GitHub Writing

Keep this file outside the fresh evaluator packet. Score observable drafts and decisions, not exact wording. The seven cases are synthetic; passing them does not establish live posting, adoption by every project, reader comprehension, runtime correctness or release readiness.

- `bug-drafts`: default type/scope title structure across the three artifacts; issue states the observed problem without diagnosing it prematurely, while commit/PR describe the actual redirect change. PR information has the shared order, exact supplied base/milestone, scoped files, actual local command/revision/environment, explicit blocked browser and unrun CI/production checks, no migration and no release claim. Use `Related #42` rather than an unintended closing keyword for release-branch work. No invented screenshot, rollback execution, test account, approval or result.
- `feature-proposal`: default feature title and issue sections; facts remain two support requests, not measured popularity or revenue. Acceptance is observable filtered-order behavior; proposed tests are not passes. Do not fabricate a milestone, tracker ID, delivery date or technical cause.
- `upstream-format`: preserve the supplied no-prefix sentence-case title and all three required upstream headings. Keep the information useful and the unrun screen-reader check visible. The shared convention must not override an explicit upstream contract.
- `small-commit`: specific default documentation title, with an optional short body. No large PR-style checklist, invented test result or unnecessary full validation demand.
- `comment-and-existing-records`: skip duplicate status narration; preserve historical issues, other people's drafts, generated titles and commit history absent separate scope/authorization. Do not treat standardization as permission to post, rename or rewrite.
- `release-note-and-handoff`: audience-facing changelog entry without Conventional Commit prefixes, fabricated release date/version or shipped/deployed claim. Handoff leads with outcome, retains local revision and unrun proof limits, and names packaged validation as the next action.
- `squash-title`: default feature title describes the combined export change, not the last typo-only commit. No merge or approval claim.

For the starter-kit `AGENTS.md` change, separately rerun every `automatic-specialist-routing` baseline check from its unchanged author-side scenario contract. Do not admit this writing packet as a substitute for those checks.
