# Explanatory diagrams: development fixture

Keep this file outside the performer packet. Inspect the delivered SVG rendered at both CSS widths, not just its XML or accompanying prose. This is one synthetic documentation repair, not a hidden benchmark or a production-system test.

| Check | What a reader must be able to establish |
| --- | --- |
| Direction | Availability permits Submitted to become Ready for pickup. Collection leads from Ready for pickup to Collected, never the reverse. Conditions belong to the correct transitions. |
| Exception and uncertainty | An unavailable item leaves the request in Submitted. The graphic does not invent expiry, email, or another transition. Prose cannot excuse a contradictory drawing. |
| Delivery | The SVG contains editable text and shapes, no external dependencies, and a useful text equivalent in the handoff. The graphic and help text agree on states, conditions, and outcome. |
| Render | Inspect 340 and 680 CSS pixels. Edges visibly attach at the intended ends; labels and arrowheads are readable and unambiguous, not cropped or merged. Relationships can be followed without color. Record actual widths, artifact identity and limits. |
| Restraint | The separate footer changes exactly the requested label, with surrounding copy intact. No extra design, workflow or unsupported proof. |
