# Eight studio requests

1. **Pocket greenhouse.** The team ships Unity 2022.3 on Android. After an artist moved materials outside the Editor without their sidecar files, several planters lost references. Some other planters are pink only in the release phone's low-quality tier, not on desktop. The replacement laptop has only Unity 6, and a colleague proposes upgrading and switching to HDRP. What do you do first, and what phone evidence would close the issue?
2. **The clock room.** A Unity 6 game uses dynamic Input System updates and Rigidbody movement. In the Editor it starts in the clock room; in the Web build it starts elsewhere. The clock room is already in the global scene list. A quick tap sometimes does nothing during a long frame. The deployed Brotli build also fails to start on a clean browser at a different host, while Build and Run works locally. How would you separate these failures and verify the fix?
3. **Museum lens.** An interactive Three.js exhibit sits in a scrollable article. The installed game and the loader from a CDN use different releases. The model loads in development but a decoder is missing under the production subpath. On a high-DPI tablet the highlighted lens is not the one tapped after resizing. A mouse user clicks a lens and tries the arrow keys; the page scrolls instead. The drag handler cancels the default press. The fleet supports WebGL 2 but no WebGPU. Choose a delivery and picking fix. How do keyboard-only and mouse-to-keyboard users complete the same inspection and then go back to reading the article?
4. **Workshop replay.** A Three.js game is mounted inside an app that owns its animation loop. After ten restarts one key press fires several times, the GPU texture count keeps climbing, and another room loses its shared wall texture. After hiding the tab while holding a movement key, the player leaps forward on return. What owns these resources and clocks, and how would you distinguish a repair from a lucky first run?
5. **Trail club.** A Godot 4 C# desktop game uses Forward+. The club wants the exact same game playable in an embedded WebGL 2 browser with no cross-origin isolation and will not pay for streaming. Can the current project be exported as-is? A separate, small GDScript browser prototype is negotiable: what would have to change, and how would you prove it works on that host?
6. **Station lift.** A Godot 4 GDScript game must run offline as a native desktop export. Running the open room in the editor works; the exported game opens in the wrong room, a constructed resource path differs from the filename only by case, and it writes progress beneath `res://`. The pause overlay cannot unpause. What would you inspect, and what must be reproduced in the exported player rather than the editor?
7. **Long weekend.** A local browser puzzle shows "saved" on an IndexedDB request's success callback. A tester loses a checkpoint after an aborted transaction. A supported old save, a truncated slot, and a slot from a newer app version all exist. A designer proposes wiping any slot the current game cannot decode. How do you ship recovery without destroying progress, and what do you verify after relaunch?
8. **One ticket.** In an existing cooperative game, two clients sometimes receive the last ticket. One goes offline before acknowledgement and resends the same claim after reconnecting. Pausing one client's menu must not stop the other player's session. The team has one scripted in-process simulation and no budget for new services. Describe who decides the outcome, what happens on reconnect, and the cheapest credible playtest.
